# 从 A 版到 C 版的手把手学习指南

日期：2026 年 10 月 26 日。

你当前有了可切换的 A/B/C 实现和源码快照。学习顺序是先看结果、再理解单个函数、最后进行真实 API 实验。代码快照是保存点，不是已经取得的比赛成绩。

## 1 每一版需要保存吗

需要保存 A、B、C 这三个有意义的阶段。每次改一个参数不必复制整个项目；在实验记录里保存参数和结果即可。现在用源码 ZIP 快照保存，后续熟悉 Git 后可以改用 commit/tag。

| 保存内容 | 用途 |
|---|---|
| 代码和依赖版本 | 知道当时运行了什么 |
| 检索模式与参数 | 知道是 A、B 还是 C，以及 RRF/上下文预算 |
| 测试题选择、数据来源与版本标识 | 保证对比的是同一批题 |
| 结果、耗时、调用成本 | 判断增加的模块是否值得 |

不要为每版复制虚拟环境、密钥、模型缓存或完整数据库。它们不属于源码快照。实验数据按其许可和比赛的数据保留规则管理，不能因为做备份就无限期保留。

本次已清除 test_api.py 中一条疑似访问口令注释，A 快照是在清除后保存的，检索算法仍是原始 A。现有 memories.db 本次没有打开或修改；验证使用独立临时数据库。

源码保存点位于项目的 `versions` 文件夹：

```text
E:\Mem\versions\
    A-dense-v1.zip
    B-hybrid-v1.zip
    C-context-v1.zip
```

A 保存修改前的原始实现；B/C 共享可切换算法代码，快照中的默认模式分别设为 hybrid/context。每个 ZIP 中的 VERSION_MANIFEST.json 记录源码 SHA-256、模式和运行库版本。当前工作目录的默认模式是 C。

以后保存一个新的实验版本：

```powershell
cd E:\Mem
.\.venv\Scripts\python.exe scripts\save_checkpoint.py C --revision v2
```

同名快照会拒绝覆盖。恢复时先解压到一个新文件夹检查，不要直接覆盖当前项目或数据库。外部 MEMORY_RETRIEVAL_MODE 环境变量仍会覆盖快照默认值，恢复后要同时核对它。

## 2 先运行一个完全离线的例子

打开 PowerShell，执行：

```powershell
cd E:\Mem
.\.venv\Scripts\python.exe scripts\compare_versions_demo.py
```

这条命令不需要打开服务，也不需要任何 Key，不读取原有数据库，不调用付费 API。它用人工设置的二维向量演示三个版本。真实服务仍用 1024 维 text-embedding-v4。

人工例子包含：

```text
ID 1：我妹妹最近换工作了。
ID 2：她去了杭州的星河医院。
ID 3：医院附近有一家咖啡店。
ID 4：我周末常去公园散步。
ID 5：星河医院的预约电话是 555-0101。（特意不提供向量）
```

例子中的 ID 1/2 属于同一批、同一会话，其他记录属于不同会话。查询是“星河医院”，top_k=3。

预期输出的 ID：

| 版本 | ID 顺序 | 观察点 |
|---|---|---|
| A | 2、3、4 | 完全按人工向量相似度排序 |
| B | 2、3、5 | BM25 可以找回没有向量的电话记录 |
| C | 2、3、1 | 上下文预算补回“妹妹”这句话，帮助理解“她” |

这里的人工向量刻意设置成容易观察差别，不能据此宣称 C 在真实问题上优于 A/B。C 把电话记录换成上下文可能有利，也可能有害，正是后续实验要衡量的取舍。

结果同时写入 `experiments/synthetic-ABC-demo.json`，文件里明确标记 synthetic=true。

## 3 A 到 B 学哪些函数

打开 ranking.py，按顺序读以下函数：

### tokenize

把文本转换成可比较的词项。英文按词切分并去除少量停用词，中文提取单字和连续双字。例如“杭州”能与“我目前住在杭州。”中的“杭州”双字匹配。这不是完整的语言学分词器，也不保证理解同义词。

### bm25_rank

统计当前用户的文档词频、文档长度和每个词出现过多少篇文档，然后按 BM25 公式计算相关性。平均长度只计算一次。没有命中的记录不进入 BM25 列表。

向量检索关注语义接近；BM25 关注词项重合。两路读取同一张 memories 表，使用相同的记录 ID。即使某条记录的向量为空，仍可以参与 BM25。

### rrf_fuse

只根据名次计算融合分数：

```text
score(id) = 1 / (60 + 向量名次) + 1 / (60 + BM25名次)
```

只出现在一路就只加那一路。第 1 名从 1 开始。相同 ID 合并成一条，不把两路原始分数直接相加。RRF 分数不是概率，不适合照搬余弦相似度阈值。

当前候选深度为 `max(50, 3 * top_k)`，每路取这么多候选后融合，再返回 top_k。常数只是初始配置，没有通过质量实验调优。

练习：在人工示例里修改查询和 top_k，观察两路命中与融合结果；如果修改参数，先记下原值，比较后决定是否保存新快照。

## 4 B 到 C 学哪些函数

### find_neighbors

只找同一 user_id、同一 session_id 下的邻居：

1. 优先使用同一次 Add 的 source_request_id + message_index。
2. 跨 Add 只有在该会话全部来源时间存在且唯一时，才使用明确的时间顺序。
3. 没有可靠序号或时间时，不把数据库 ID 当对话顺序，不猜测邻居。

message_index 是消息在本次 Add 的列表位置，第一条为 0。即使并发请求的到达顺序不同，也不能改变这个来源序号。

### add_context

先保留主要检索命中，再分配有限名额给前后各一条消息。当前上下文预算为返回规模的 25% 向上取整，并至少保留一个主要命中；top_k=1 时不扩展。小 top_k 因为取整，实际比例可能高于 25%。未用满的名额再用原排名补齐。

最多从前 10 个主要命中扩展。同一来源 ID 只出现一次；相关分数按父命中的分数衰减，并与其原有检索分数取较大值，最后保持分数降序。这个衰减只是初始化启发式规则，仍需要实验。

最后把角色和已知来源时间显示在原文前：

```text
[role=user; source_time=2026-10-01T00:00:00+00:00]
原始消息完整内容
```

没有时间就明确显示 unknown，不使用服务器当前时间。C 没有实现“新事实一定覆盖旧事实”的判断，也没有自动摘要或生成答案。

## 5 在同一份代码中切换 A B C

不需要解压快照才能切换。使用启动服务的 PowerShell 设置模式，然后启动或重启服务：

```powershell
$env:MEMORY_RETRIEVAL_MODE = 'dense'    # A
$env:MEMORY_RETRIEVAL_MODE = 'hybrid'   # B
$env:MEMORY_RETRIEVAL_MODE = 'context'  # C
```

上面三行是三种可选写法；实际只执行你要用的那一行，依次执行三行最终会选择 C。只修改另一个终端的变量，不会改变已经运行的服务进程。

项目中 `semantic_search()` 仍然固定调用 A 版，保持旧学习脚本兼容；HTTP `/search` 调用的是新入口 `search_memories()`，由上述模式控制。

当前 BM25 是从该用户记录临时构建的，Add 不需要另外运行“建 BM25 索引”脚本。每次 Search 重建的成本在长历史上需要测量，后续可考虑增量索引或 FTS5。

## 8 后续真实实验怎么保存

实验记录至少包含：run_id、代码快照名、模式、RRF 参数、上下文比例、数据来源/版本、题目选择、回答/裁判配置（若使用）、质量指标、延迟、返回文本量和成本。不要记录密钥。

先比较 A 与 B，再比较 B 与 C。每次只改变一个模块；相同题目与预算下，记录改善和退化的题目。不要只看一个演示成功就认定 C 一定更好。
